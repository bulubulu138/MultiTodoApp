# 待办紧急程度设计

## 背景

当前待办的 `priority` 表示工作类型（脑力劳动、沟通对齐、临时小活），不能表达某件事是否应该优先处理。每天的“今日事”回流到“待办池”后，用户需要依据紧急程度快速筛选值得优先处理的任务。

本功能新增独立的二值字段 `urgency`，不改变现有 `priority` 的含义，也不引入 SQLite 迁移。应用当前使用 Markdown 文件作为待办的持久化来源。

## 目标

- 每个待办拥有“高”或“低”两档紧急程度。
- 新建和编辑待办都可以设置紧急程度，默认值为“低”。
- 待办池可以按“全部 / 高 / 低”筛选紧急程度。
- 每日回流只改变状态，不丢失或重置紧急程度。
- 旧 Markdown 文件没有 `urgency` 时仍可正常读取，并按“低”处理。
- Markdown 读写、文件索引、同步和相关展示路径不会丢失该字段。

## 非目标

- 不修改现有 `priority` 的三种工作类型。
- 不增加中等紧急程度或自定义紧急程度。
- 不为 SQLite 增加字段、迁移或新的查询逻辑。
- 不改变除待办池之外的 Tab 筛选规则，除非它们复用同一通用展示组件所必需。

## 数据模型与持久化

在 `src/shared/types.ts` 的 `Todo` 中增加：

```ts
urgency: 'high' | 'low';
```

Markdown frontmatter 使用以下字段：

```yaml
urgency: high
```

读取 Markdown 时只接受 `high` 和 `low`；字段缺失或值非法时归一化为 `low`。新建待办默认写入 `urgency: low`。更新待办时沿用现有文件存储的部分更新机制，只有用户明确修改紧急程度时才写入新值，回流更新状态时保留原值。

文件索引中的待办条目也要携带 `urgency`，这样从索引加载、搜索和刷新后不会出现字段丢失。同步数据和 Markdown 导入/校验路径沿用同一默认值与合法值规则。

## 用户界面

### 新建和编辑

在 `TodoForm` 的元数据区域增加“紧急程度”选择项：

- 高
- 低（默认）

编辑已有待办时显示其当前值；旧数据缺失时显示低。提交对象包含 `urgency`。

### 待办展示

在现有待办列表/卡片的元数据区域显示紧急程度标签：

- 高：使用醒目的警示色
- 低：使用中性颜色

展示应与现有优先级标签并列，不能替换或重新解释优先级标签。

### 待办池筛选

在待办池工具栏或现有筛选区域增加紧急程度筛选，选项为“全部 / 高 / 低”。默认“全部”。只有 `activeTab === 'pending'` 时显示并应用该筛选；离开待办池后筛选状态可以保留，但不影响其他 Tab 的结果。

筛选应在状态/标签/负责人等基础筛选之后、搜索之前或作为同一层基础筛选的一部分执行，确保搜索缓存键包含紧急程度筛选值，切换筛选不会复用错误结果。

## 数据流

1. Markdown 文件读取到 `FileStorageManager`。
2. `MarkdownParser` 解析并归一化 `urgency`，缺失值转为 `low`。
3. 文件索引、Renderer 状态和列表组件使用共享 `Todo` 类型。
4. `TodoForm` 创建或更新待办，并通过现有 IPC/file-storage 更新路径写回 Markdown。
5. `TodoBackflowManager` 仅更新 `status`，因此 `urgency` 原值保留。
6. 待办池基于 Renderer 当前状态按 `urgency` 过滤。

## 错误处理与兼容性

- 读取未知紧急程度时不阻塞整个文件加载，归一化为低并记录已有风格的警告（如果该解析路径已有日志机制）。
- 类型和组件对来自旧缓存或旧同步数据的缺失值使用低作为兼容回退，避免渲染时出现空标签。
- 导入 Markdown 时，非法值应按现有 frontmatter 校验策略处理；若当前导入策略允许兼容修复，则修复为低并继续导入，否则返回明确字段错误。
- 不修改用户已有的 `priority`、状态、排序、标签或负责人。

## 测试策略

- Markdown parser/file-storage 测试：`urgency: high` 和 `urgency: low` 正确读取，缺失或非法值归一化为低，写回时包含字段。
- 表单测试：新建默认低，编辑显示已有值，提交包含所选高/低值。
- 筛选测试：待办池能得到全部、高、低三种结果；其他 Tab 不受紧急程度筛选影响；切换筛选后搜索/排序缓存不会返回旧结果。
- 回流测试：状态从 `in_progress` 变为 `pending` 后，紧急程度保持不变。
- 运行现有 TypeScript/build/test 命令，确认不影响已有功能。

## 验收标准

- 用户可以在新建或编辑待办时选择高/低紧急程度。
- 关闭并重新打开应用后，紧急程度仍然正确。
- 每日回流到待办池后，紧急程度不变。
- 在待办池选择高或低时，只显示对应待办，并且搜索、排序、负责人筛选仍然正确工作。
- 历史 Markdown 文件无需手工修改即可正常使用，缺失字段显示为低。
