# 专注模式固定工具栏与设置弹窗层级设计

## 背景

专注模式中的每个待办都有自己的顶部操作栏。当前实现虽然使用了 `position: sticky`，但现有测试只验证 CSS 文本，无法保证真实滚动容器中的工具栏可用。与此同时，打开设置弹窗时，专注模式的“查看详情”按钮可能显示在弹窗或遮罩上方。

## 目标

1. 在专注模式内容区域内滚动到待办正文较低位置时，该待办的工具栏仍固定在内容区域顶部。
2. 当下一个待办进入工具栏位置时，由下一个待办的工具栏自然接替前一个工具栏。
3. 设置弹窗及其遮罩始终覆盖专注模式工具栏，不能被“查看详情”按钮遮挡。
4. 不改变待办编辑、保存、排序、关系查看和详情查看行为。

## 设计

### 固定范围

`.content-focus-scroll-area` 是专注模式唯一的滚动容器。每个 `.content-focus-item-header` 在该容器中使用 `position: sticky`，吸附位置为滚动区域顶部（`top: 0`）。工具栏使用不透明的主题背景和底部边框，避免正文滚动到其下方时发生视觉叠加。

固定工具栏属于待办自身的布局上下文，因此滚动到下一个待办时由 CSS sticky 的正常边界行为完成接替，不引入全局当前待办状态或额外滚动监听。

### 弹窗层级

设置 `SettingsModal` 使用显式的 Modal 层级，高于内容工具栏的 sticky 层级，同时保留 Ant Design 的遮罩层顺序。层级约束通过组件属性或项目现有主题样式表达，避免依赖默认值在不同 Ant Design 版本中的隐式行为。

### 响应式行为

保留现有移动端工具栏换行布局。sticky 定位仍作用于整个换行后的工具栏高度，不能使用会导致内容被裁切的固定高度。

## 测试与验收

增加或调整测试以验证：

- 专注模式存在独立滚动容器，且待办工具栏使用 sticky 定位、顶部偏移为 0、拥有内容层级和不透明背景。
- 工具栏的 sticky 规则位于实际生效的 CSS 规则中，而不是只存在于无效的重复规则或注释中。
- 设置 Modal 声明高于内容工具栏的层级，且不会依赖工具栏按钮自身降低层级来规避遮挡。
- 现有专注模式编辑、撤销和构建测试继续通过。

## 非目标

- 不实现跨待办的全局单例工具栏。
- 不修改详情抽屉本身的内容和交互。
- 不修改全局工具栏、浮动回到顶部按钮或普通/紧凑视图布局。
